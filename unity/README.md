# SoccerMaster native (Unity 6) — side-by-side project

The web app in the repository root stays the behavioral oracle. This folder is the native iPhone
implementation (v1.2 package, tickets N00–N08). Nothing here replaces or alters the web build.

```
unity/
  Assets/SoccerMaster/
    Runtime/Core/      SoccerMaster.Core   deterministic simulation port, no UnityEngine references
    Runtime/View/      SoccerMaster.View   scene adapters: forward time + input in, mirror state out
    Editor/            SoccerMaster.Editor deterministic scene builder, iOS export entry point
    Tests/EditMode     fixture parity + build-config tests
    Tests/PlayMode     runs the real FirstTouch scene
    Tests/Fixtures/first_touch_parity.json   GENERATED by `npm run native:fixtures` from the web code
  Packages/manifest.json
  ProjectSettings/ProjectVersion.txt         6000.3.24f1
  Tools/ParityCheck/                         plain .NET harness (pre-check only, not Unity evidence)
  build/test.sh, build/ios.sh                repeatable batchmode entry points
```

Boundary rule (architecture/INTEGRATION.md): `FirstTouchDrill` owns state, RNG, rules and outcomes.
`FirstTouchController` only passes wall-clock time and touch input into the drill and mirrors the
drill's committed state onto the scene. No soccer reasoning lives in a MonoBehaviour.

## First ported interaction: first-touch training

`src/training/firstTouch.ts` → `Assets/SoccerMaster/Runtime/Core/Training/FirstTouchDrill.cs`
(plus `Rng`, `Vec2D`, `JsMath`, `GestureReader`). Preserved contract: 24×18 area, receive (10,9),
server (3,9), three gates, 50 ms tick, 2.5 s real-time decision window (×1.5 accessible), 0.12×
simulated time during the window, seeded RNG, anticipatory defender, decision / execution /
outcome kept separate, timeout still commits a loose touch.

Parity is checked against fixtures the **web implementation generates**, never hand-written values:

```
npm run native:fixtures   # tools/nativeFixtures.ts → Tests/Fixtures/first_touch_parity.json
npm run native:parity     # .NET harness: replays fixture through the C# port (21,950 comparisons)
```

Tolerances: discrete state, phases, bands, gates, RNG words — exact. Kinematic doubles — 1e-9
(last-ULP differences between V8 and .NET transcendental functions).

## Unity validation environment: GitHub Actions (`.github/workflows/unity.yml`)

Uses GameCI images `unityci/editor:ubuntu-6000.3.24f1-{base,ios}-3` (verified to exist on Docker
Hub). The workflow **skips every Unity job unless a license secret exists** — it never fakes green.

One-time account-owner action (choose one):

1. **Unity Personal** (free): on any Mac/PC, sign in to Unity Hub once, then copy the file
   `Unity_lic.ulf` (macOS `/Library/Application Support/Unity/`, Windows
   `C:\ProgramData\Unity\`) into the repository secret `UNITY_LICENSE` (the file's contents).
   Alternatively run the `Activation` job of the GameCI docs (`game-ci/unity-request-activation-file`)
   and upload the `.alf` at https://license.unity3d.com/manual to obtain the `.ulf`.
2. **Unity Pro/Plus seat**: repository secrets `UNITY_SERIAL`, `UNITY_EMAIL`, `UNITY_PASSWORD`.

Then run the workflow manually (Actions → Unity → Run workflow) with
`commit_generated = true` once: Unity imports the project, builds the FirstTouch scene from code,
runs EditMode + PlayMode, uploads NUnit XML, and commits `.meta`, `packages-lock.json`,
`ProjectSettings/*.asset` and the scene back to the branch. From then on every PR touching
`unity/**` or the oracle sources runs import + both test modes automatically.

GitHub-hosted runner cost: the Unity jobs run on Linux runners (free for public repos; private
repos consume included Actions minutes at the Linux rate). No macOS runner is used until signing.

## Unity Build Automation (UBA) evaluation

- Public UBA docs list Unity 6000.0 and 6000.1 build images; 6000.3 was **not** listed when checked,
  so UBA cannot be treated as available for this project's editor line without confirming in the
  Unity Cloud dashboard of the owning organization (Unity DevOps → Build Automation → New config →
  Unity version dropdown). Do not pin a UBA image before that check.
- Pricing (public page, verify in-dashboard before enabling): free tier includes Mac build minutes;
  additional Mac minutes are metered (~$0.07/min). Enabling DevOps on the organization is a
  billing-relevant toggle → owner decision, not enabled by Devin.
- UBA is only needed for the **macOS/Xcode signing + upload** stages. Import/tests/Xcode export are
  covered by GitHub Actions on Linux above.

## Repeatable entry points

```
UNITY_EDITOR=/path/to/Unity unity/build/test.sh all        # EditMode + PlayMode, XML in build/logs
UNITY_EDITOR=/path/to/Unity SM_BUILD_NUMBER=42 unity/build/ios.sh
```

`IosBuild.Build` (Editor/IosBuild.cs) fails with `BuildFailedException` when the required scene is
missing, the bundle id is not reverse-DNS, the version is not `major.minor.patch`, or the build
number is not a positive integer. Env: `SM_IOS_OUTPUT`, `SM_BUNDLE_ID` (default
`com.codyengilman.soccermaster`), `SM_APP_VERSION` (default `0.1.0`), `SM_BUILD_NUMBER`,
`SM_GIT_SHA`. It writes `Assets/SoccerMaster/Resources/build_info.json` (git-ignored) so the app
can display version/build/commit. Automatic signing is disabled; no team id or profile is set here.

## Delivery stages after Unity tests (each is its own evidence gate)

1. Native build: Xcode project export (Actions, Linux) → archive + sign (needs macOS: UBA, a
   GitHub macOS runner, or the owner's Mac). Signing material (App Store distribution
   certificate, provisioning profile, App Store Connect API key) goes only into the build
   service's secret store — never the repo, chat, logs or screenshots.
2. App Store Connect upload (API key `Issuer ID` / `Key ID` / `.p8` in service secrets).
3. Apple processing → TestFlight build available.
4. Internal tester assignment → install on the owner's iPhone.
5. Gameplay on device: first-touch drill, save/reload, background/resume, build number shown.

One-time account-owner actions for those stages: Apple Developer Program membership, App ID
`com.codyengilman.soccermaster` in the developer portal, App Store Connect app record, an API key
with App Manager role, and the iPhone added as an internal TestFlight tester.
